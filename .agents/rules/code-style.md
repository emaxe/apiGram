# Стиль кода

## Общее

- ESM (`"type": "module"`), Node >= 18, без транспиляции и без TypeScript.
- Отступ — 4 пробела. Двойные кавычки. Точки с запятой.
- Комментарии и JSDoc — на русском. Названия идентификаторов — на английском.
- Комментарий объясняет **почему**, а не пересказывает код. Особенно ценны те, что
  фиксируют неочевидное поведение teleproto или причину обходного пути.
- Никаких новых зависимостей без необходимости: сейчас это `express`, `multer`, `ws`,
  `dotenv`, `teleproto` — и всё.

## Слои

Направление зависимостей строго одностороннее:

```
index.js → server/ → telegram/ → registry/ → storage/
                          ↘ config.js ↙
```

`telegram/` ничего не знает про Express: не принимает `req`/`res` и не формирует HTTP-коды.
`server/` не дёргает TL-методы напрямую — только через модули `telegram/`.

## Ошибки

- Наружу ошибки уходят единственным путём: `next(err)` → error-middleware → `toHttpError`
  (`src/server/httpErrors.js`). Не писать `res.status(500)` руками и не глотать исключения.
- Новый класс ошибок MTProto добавляется в маппинг `httpErrors.js` вместе с юнит-тестом.
- Формат тела ошибки: `{ error, message, step?, hint?, seconds? }`. `error` — стабильный
  машиночитаемый код в `snake_case`, `message` — человекочитаемое пояснение.

## Роуты

- Каждый обработчик — `async (req, res, next)` с `try { … } catch (err) { next(err); }`.
- Клиент берётся только через хелпер `getClient(req)`.
- Секции роутера разделены комментарными заголовками (`// ── Сообщения ───`), новый
  эндпоинт кладётся в свою секцию, а не в конец файла.

## Тесты

`node --test test/unit.test.js`, без фреймворков. Каждое исправление протокольного бага
сопровождается тестом на маппер или сериализацию — то, что проверяемо без живого аккаунта.
Живые сценарии — в `scripts/smoke.mjs`, они не входят в `npm test`.
