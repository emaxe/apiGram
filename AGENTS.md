# apiGram

Multi-user Telegram API gateway (MTProto) — REST + WebSocket. Один Node-процесс держит пул
`TelegramClient` по одному на аккаунт, отдаёт REST под `/v1` и realtime-поток по
`/v1/ws`. Точка входа — `src/index.js`.

## Мета

Перед добавлением или изменением правил, скилов, инструкций -- прочитай скилл
`agents-conventions`.

## Структура

| Каталог | Что внутри |
|---|---|
| `src/server/` | HTTP-слой: Express-приложение, роутер, Bearer-проверка, маппинг ошибок, WS |
| `src/telegram/` | Протокольный слой: клиент, пул сессий, авторизация, сообщения, диалоги, профиль, слушатель обновлений |
| `src/registry/` | Реестр аккаунтов поверх `data/accounts.json` |
| `src/storage/` | Атомарная запись JSON и JSONL с ротацией |
| `scripts/smoke.mjs` | Сквозная проверка на живом аккаунте |
| `test/unit.test.js` | Юнит-тесты (`node --test`) |

## Команды

```bash
npm start        # запуск сервера
npm test         # юнит-тесты
./run.sh         # интерактивный помощник: dev, smoke, env, health, doctor, clean
```

## Правила

### Секреты и пользовательские данные
`data/` и `.env` содержат сессии Telegram, токены и телефоны — это боевые учётные данные,
а не тестовые фикстуры. Никогда не коммить их, не печатать в логи и не переносить в
примеры.
[Подробности](.agents/rules/secrets-and-data.md)

### Вызовы teleproto
Сигнатуры `teleproto` расходятся с интуицией и с документацией gramjs: часть
высокоуровневых хелперов непригодна, нужен raw TL. Перед вызовом нового метода —
проверить его реальную сигнатуру в `node_modules/teleproto`, а не по памяти.
[Подробности](.agents/rules/teleproto-api.md)

### Стиль кода
ESM, отступ 4 пробела, JSDoc и комментарии на русском, двойные кавычки. Ошибки наружу —
только через `toHttpError`, никаких `res.status(500)` вручную.
[Подробности](.agents/rules/code-style.md)
